\section{اجرای محلی}
اجرای محلی پروژه با \lr{Docker Compose} انجام می‌شود:
\begin{latin}
\begin{lstlisting}
docker compose up --build
\end{lstlisting}
\end{latin}

در این پیکربندی، سمت کاربر روی \lr{http://localhost:5173} و سمت سرور روی \lr{http://localhost:8000/api} منتشر می‌شود.

این روش برای بررسی سریع کل سامانه مناسب است، زیرا هر دو بخش اصلی را هم‌زمان بالا می‌آورد. پس از اجرا، کاربر می‌تواند ابتدا مسیر سلامت سمت سرور را بررسی کند و سپس از طریق سمت کاربر وارد جریان مرور فهرست، ورود، پیشخوان و ابزارهای توسعه‌دهنده شود. اگر یکی از سرویس‌ها اجرا نشود، باید گزارش همان سرویس در \lr{Docker Compose} بررسی شود.

\section{اجرای آزمون سمت سرور}
دستور اجراشده در این گزارش:
\begin{latin}
\begin{lstlisting}
python manage.py test api
\end{lstlisting}
\end{latin}
در نسخه فعلی، مجموعه آزمون شامل \lr{109} آزمون سمت سرور است. اجرای آن روی پایگاه ایزوله انجام می‌شود؛ پایگاه روی \lr{MongoDB} ساخته و پس از آزمون حذف می‌شود. آخرین اجرای کامل نسخه جاری \lr{109/109} آزمون را با موفقیت گذراند.

این دستور فقط آزمون‌های برنامه \lr{api} را اجرا می‌کند و برای تکرار نتیجه فصل آزمون کافی است. در صورت تغییر کد سمت سرور، اجرای دوباره این دستور باید نخستین کنترل کیفی باشد. برای تغییرات سمت کاربر، اجرای آزمون‌های مرورگر و ساخت نسخه سمت کاربر نیز باید به این کنترل اضافه شود.

\section{کنترل کامل و استقرار زنده}
دستورهای تکمیلی زیر کیفیت سمت کاربر، کارخواه و مرورگر را بررسی می‌کنند:
\begin{latin}
\begin{lstlisting}
cd api-hub-express
npm run check:i18n
npm run lint
npx tsc -b --pretty false
npm run build
npx playwright test

cd ../iranapi-cli
npm test
\end{lstlisting}
\end{latin}

نسخه \lr{v21} روی \lr{Runflare} فعال است. دامنه موقت یک‌ساعته عمداً در گزارش ثابت نشده است؛ کارخواه نشانی جاری را از \lr{/cli/manifest.json} همان میزبان دریافت و ذخیره می‌کند:
\begin{latin}
\begin{lstlisting}
iranapi doctor --api-url https://<current-domain>/api/v1 --json
iranapi apis list --api-url https://<current-domain>/api/v1 --limit 2 --json
\end{lstlisting}
\end{latin}
